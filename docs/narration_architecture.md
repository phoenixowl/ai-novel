# 旁白系统代码结构与调用链分析

这份文档解释旁白系统的代码是怎么组织的、一个回合在程序内部是怎么流转的。
读它不需要预先了解任何东西——所有名词在用到的地方都会解释。
设计层面的"为什么"见 `docs/narration_design.md`（含 2026-10 裁剪的变更记录）；本文只讲"现在代码里它是怎么跑的"。

---

## 一、旁白是什么：一句话定位

这个游戏里有两套**相互独立**的回应系统：

| | 对话系统 | 旁白系统（本文主角） |
|---|---|---|
| 玩家对谁说话 | 一个有名有姓的 NPC | **整个世界** |
| 玩家输入什么 | 台词（"掌柜的，这茶怎么卖？"） | 行动声明（"我从书架上抽一本书"） |
| 谁来回应 | 以 NPC 身份说话的模型 | 以"世界主持人"身份说话的模型 |

两者是**两个独立的输入界面**（主菜单「探索世界」与「人物对话」），程序不做任何路由判断；
两套数据也完全独立——旁白的事实库不进对话材料包，对话的产物不回写旁白域
（2026-10 裁剪，重接桥的恢复点见设计文档变更记录）。

旁白系统的核心承诺：**模型可以即兴创造世界细节（自由度），但凡是"以后还会被用到"
的东西都必须显式登记进一个引擎维护的账本（一致性）**。这个账本叫
**世界事实库（正典，Canon）**，它是整个系统的中枢。

---

## 二、代码长什么样：一个域、七个文件

按照全项目的五家族命名规则，旁白是一个业务域，`Scripts/Narration/`：

| 文件 | 行数 | 家族 | 一句话职责 |
|---|---|---|---|
| `narration_controller.gd` | 346 | 控制器 | 指挥官：接收行动、推进回合、落地结果、管回滚与旋钮 |
| `narration_events.gd` | 31 | 契约 | 信号声明清单（UI 与控制器之间所有消息的名字） |
| `canon_store.gd` | 191 | 存取器 | 世界事实账本：记、改（只标不删）、压缩、快照 |
| `narration_pack.gd` | 56 | 模型 | 旁白材料包：一个回合需要看的一切，装完冻结 |
| `narration_pack_builder.gd` | 26 | 处理器 | 把材料装进材料包 |
| `narration_prompt_builder.gd` | 126 | 处理器 | 两层提示词：静态规则（缓存）+ 本回合材料 |
| `narration_parser.gd` | 84 | 处理器 | 检查模型输出：合法的收下，非法的修复或丢弃 |

加上界面 `Scripts/UI/narration_screen.gd`（325 行）与场景 `Scenes/narration_screen.tscn`。
旁白控制器以 autoload 注册为 `"Narration"`，顺序：Events（总线）→ LLM → Characters
→ **Narration** → Dialogue。数据落在 `saves/world/canon.json`（唯一持久状态，
删掉即世界重置）；`res://settings/mainline.txt` 是作者写的主线基调（只读）。

## 三、一次旁白回合的完整调用链

### 第 1 步：提交

```
玩家在探索屏输入"我从书架上抽一本书"，回车
→ narration_screen.gd::_send()：检查 _can_accept（等待期才放行）
→ 发命令信号：NarrationEvents.cmd_submit_action
→ NarrationController::_on_cmd_submit_action()
   剔除空白 → 回合号 +1 → 事件流水记一条 player_action → 状态切到"旁白叙述中"
```

状态机只有两个状态：**等待你的行动**和**旁白叙述中**（没有轮次上限——探索是自由的）。
"旁白叙述中"时输入框与回滚按钮全部置灰，防止并发。

### 第 2 步：冻结现场（材料包）

```
→ _narrate()：NarrationPackBuilder.build() 组装旁白材料包
   装进去的东西：
   · 世界观全文 + 主线基调      （作者写的，res://settings/）
   · 世界事实库（带编号，最多 120 条，超了按规则压缩）
   · 近期旁白流水（最近 8 行）   （"上一回合发生过什么"）
   · 玩家行动原文               （一字不改）
→ 发 pack_built：调试侧栏②页立刻显示
```

组装完成后材料包**冻结**——模型这一回合只能基于这个瞬间作答。

### 第 3 步：拼提示词

```
→ NarrationPromptBuilder.system_prompt()   静态规则层：GM 身份、裁决准则、
   事实纪律（三条铁律）、采纳准则、防注入条款、输出格式
   —— 按四个风格旋钮的组合缓存
→ NarrationPromptBuilder.user_prompt()     材料层：把材料包渲染成文字
→ 发 prompt_built：调试侧栏③页显示两层全文（可一键复制）
```

静态层最重要的三条**事实纪律**：①不可违背世界观与正典；②要和既有事实"对着干"
只能走 `facts[].ref` 的取代通道；③叙述里出现的、后面情节可能依赖的东西必须显式
写进 `facts`，纯氛围可以只留在叙述里。这三条就是"自由度与一致性的分界线"。

### 第 4 步：生成

```
→ await LLMController.complete_json(静态层, 材料层, purpose=NARRATION)
```

两种失败各有一条出路：**传输失败**什么都不落地、回到等待让玩家重试（行动事件
留在流水里）；**输出不可解析**注入保底旁白"你愣了一下，什么也没发生"
（裁决 pending、零事实、不改世界——宁可平淡，不可胡说）。

### 第 5 步：校验（受控开放）

模型被要求只输出一个 JSON 对象，`NarrationParser.validate()` 逐字段检查。
输出契约只有三字段：

| 字段 | 检查方式 |
|---|---|
| `narration` 叙述文本 | 完全开放（这是模型发挥文采的地方） |
| `outcome` 裁决 | 四选一枚举（success/partial/failure/pending），非法回落 pending |
| `facts[].ref` 改写引用 | **闭集**：编号必须在本回合材料包展示过的正典里；越界降级为新事实 |
| `facts[].content` 新事实 | 开放生成——空 content 丢弃 |
| `facts[].weight` 权重 | 二选一枚举（major/minor） |
| `adopted_from_player` | true 则标记来源为"玩家设想" |

正典门槛=严格时，这里会丢弃 minor 级新事实（只留 major 和改写）——设置旋钮的生效点之一。

### 第 6 步：落地（先拍照，再动账本）

```
→ _land()：
   ① 先存快照：CanonStore.snapshot()          ← 回滚的前提
   ② 逐条处理 facts：ref>0 走取代（旧条目标 superseded 指向新条目），
      ref=0 新确立（精确去重）→ 每条发 fact_established / fact_superseded
   ③ 发 narration_turn（叙述本体 + 裁决结果）
   ④ 有事实变化：落盘 saves/world/ + 重发 canon_listed
   ⑤ 状态回到"等待你的行动"
```

注意顺序：**快照在所有写入之前**。

## 四、世界事实库：账本的四条规则

`CanonStore` 是全系统的中枢，理解它只需要四条：

**1. 每条事实带来源。** `narrator`（旁白确立）或 `player`（玩家发明、被旁白采纳）。
来源不改事实的地位，但会被标注——材料包里"源自对方的设想"的条目模型可另行对待。

**2. 改写 = 标记取代，不删除。** 旧条目打上 `superseded` 标记并指向新条目——
任何历史快照恢复回来都不会有悬空引用，每次改写都留了审计痕迹
（调试侧栏①页显示"改写 N 次"）。

**3. 有去重和预算。** 同一表述重复确立不产生重复条目；账本超过 120 条时
major 全保、minor 只保最近 20 条——重大的事永远在，琐碎的事随时间淡忘。

**4. 唯一持久状态。** `saves/world/canon.json` 是旁白域的全部落盘数据；
对话日志、人物快照、好感度都在各自的目录里，互不相扰。

## 五、回滚：先拍照，再动账本

旁白的事实必须**即时生效**（这轮书架上有书，下轮就要能取），不能延后结算。
所以回滚靠**回合快照链**：

```
每个回合落地前：CanonStore.snapshot()（内存深拷贝）
回滚到回合 N：
→ _session += 1                 ← 生成窗口内回滚，在途回应恢复后发现编号变了，自行丢弃
→ 删掉回合 ≥ N 的所有事件
→ 恢复第 N-1 回合落地前的快照，并截断其后的快照
→ 落盘 + 发 rolled_back + 重发世界事实
```

效果：回滚第 3 回合，该回合确立的事实、改写操作全部消失，世界回到第 2 回合
结束时的样子；已落盘的 canon.json 同步写回，重启游戏后回滚依然成立。

## 六、四个风格旋钮

设置屏的"旁白风格"区（采纳度 / 裁决倾向 / 描写密度 / 正典门槛，各两档）：

```
设置屏改下拉 → cmd_set_knobs → 控制器写入 GameConfig（user://config.cfg）
→ 清提示词缓存 → 发 knobs_changed → 设置屏回填
```

旋钮只改变**提示词措辞**（裁决宽严、采纳倾向、叙述详略）和**解析器的入库门槛**
（严格时 minor 新事实不入正典）——不改变数据结构与校验规则。静态层按旋钮组合缓存，
换档后下一回合自动用新风格。

## 七、旁白记录在界面上长什么样

| 事件 | 界面表现 |
|---|---|
| `player_action` | 蓝色"你（行动）："气泡，带 ↩ 回滚按钮 |
| `narration_turn` | 灰色叙述正文，前面带〔success〕之类的裁决标签 |
| `fact_established` | 一行小字"世界多了一条事实 [编号]：……" |
| `fact_superseded` | 一行小字"事实 [编号] 被改写" |

所有事件同时写入 `user://dialogue_logs/narration_*.jsonl` 审计文件。
调试侧栏四页：**①世界事实**（正典全量，superseded 折叠成"改写 N 次"）、
②材料包、③完整提示词（可复制）、④模型回应。

一个值得知道的细节：控制器初始就处于"等待你的行动"并广播了一次状态，
但那时探索屏可能还没初始化。所以探索屏就绪和每次进屏时都会发 `cmd_get_state`
主动**补拉**一次状态——否则输入框会永远停在禁用（这个 bug 真实发生过，
修的时候加了回归测试）。

## 八、测试与想改从哪里下手

| 测试 | 覆盖 |
|---|---|
| `smoke_test.gd` 旁白单元块 | 正典去重/取代链/预算压缩/快照恢复；解析器闭集/降级/门槛/来源映射；提示词两档措辞与缓存 |
| `narration_loop_test.gd`（端到端，16 项） | 离线全链路：翻书回合落地 → 状态补拉 → 回滚恢复 → 生成窗口内回滚丢在途 → 持久化 |
| `engine_loop_test.gd` | 对话域回归（不涉及旁白域） |

| 想做的事 | 改哪里 |
|---|---|
| 调整裁决/叙述风格 | `narration_prompt_builder.gd` 的 `_build_system` |
| 给正典条目加新字段 | `canon_store.gd` 条目结构 + `narration_parser.gd` + `narration_pack` 渲染 |
| 加新的裁决结果档 | `narration_parser.gd` 的 OUTCOMES + 提示词 + UI 标签 |
| 重接对话桥（恢复 2026-10 裁剪） | 见 `narration_design.md` 变更记录里的恢复点清单 |
| 历史重放（回滚后不丢气泡） | 探索屏 `_on_rolled_back` 按 `narration.events` 重建（数据都在流水里） |

原则与全项目一致：**控制器收命令发事件，处理器只加工，存取器只进出数据；
UI 只连信号、发命令**。旁白域与对话域、人物域之间没有任何函数调用与数据交换。
